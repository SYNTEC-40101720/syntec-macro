## Phase 1 — 默认 backend 切换决策门（Rust 收益评估）

**总目标**：让 Rust/Wasm backend 在 fixture / large-20k / nav-500-files 三场景稳定优于或等于 JS（p50/p95/max 误差 ≤ 5%），fallback 持续 0%，作为切换默认 backend 的前置证据。

**当前基线**（2026-09-20 dev machine，`npm.cmd run benchmark:compare -- --iterations 3 --no-threshold --json`）：
- fixture：JS p50 ~18ms，Rust ~17ms，parity=equal，fallback=0
- large-20k：JS p50 ~383ms，Rust ~281ms，parity=equal，fallback=0
- nav-500-files：JS batch ~402ms，Rust batch ~324ms，parity=equal，fallback=0

> 注：当前 3 次样本显示 Rust 已不再复现 v3.0.0 当时的 8.3% 回归；但样本量不足以直接切换默认 backend，需 ≥5 次稳定采集 + CI 双平台对照才可判定。

### 步骤

1. **建立性能历史 baseline 文件** ✅ **已完成（2026-09-20）** — 在仓内新增 `perf-baseline/v3.0.0.json`（schemaVersion+tag+collectedAt+platform+nodeVersion+gitCommit+wasmArtifact{path,byteLength,sha256}+iterations+results[]{scenario,lineCount,js.p50Ms,rust.p50Ms,parity}+nav{rustBatchMs,parity}+fallback+regressions+summary）作为已发布版本节点的靴子基线。新增 `perf-baseline/README.md` 说明用途 + 文件规则 + 后续采集清单 + 切换默认 backend 的决策门。`.vscodeignore` 显式排除 `perf-baseline/`/`perf-data/` 不入 VSIX。
   - 入口文件：`perf-baseline/v3.0.0.json`、`perf-baseline/README.md`、`.vscodeignore`
   - 验收：`npm test` 仍全绿；`check:vsix` 不把 `perf-baseline/` 误入 VSIX
   - 阻塞：无
   - 风险：避免 baseline 文件随每次基准滚动写入——已发布版本节点的 baseline 一写不再改

2. **采集稳定性能证据 ≥5 次** ✅ **已完成（2026-09-20 dev machine）** — dev machine (Windows) 跑 5 次采集：fixture JS p50 [9.57..10.34]ms / Rust p50 [9.67..10.72]ms (Rust 慵约 1%, 0.1ms 绝对值)；large-20k JS p50 [371..500]ms / Rust p50 [265..340]ms (Rust 快约 26%)；nav-500-files batch JS [400..450]ms / Rust [330..360]ms (Rust 快约 18%)；parity 全等价；fallback 0/5 (0%)。**CI Linux + CI Windows 双平台数据仍待累积**（需 user push 触发 rust-wasm.yml workflow ≥5 次）。
   - 验收：5 次 dev stable 采集已入 `perf-data/benchmark-windows-dev-run1..5.json`；CI 平台数据从 `actions/upload-artifact@v4` 下载 `p1-perf-ubuntu-latest.json` / `p1-perf-windows-latest.json`
   - 阻塞：CI 历史数据需 ≥5 次推送（用户侧）
   - 风险：CI runner 速度基线 ≠ dev machine；按 platform 分开采集，不混用阈值

3. **Rust large-20k 热路径分析与优化** ⏸️ **不必要 - 跳过（2026-09-20）** — v3.0.0 baseline 当时的 large-20k Rust 慵 8.3% 回归已在 Phase 1.2 的 5 次采集下自然消失，Rust 现稳定领先 JS 约 26%（278ms vs 383ms）。fixture 上 Rust 慵 JS 约 0.1ms (绝对值 0.1ms) 在可接受噪声范围（单次 ~10ms 与 wasm startup 7.5ms 接近）。Phase 1.3 作为未来 Rust 被回归时的备用优化保留，不主动推进。

4. **更新 `REGRESSION_THRESHOLDS` 为 Rust 收敛值** ✅ **已完成（2026-09-20 dev machine）** — 把 `scripts/benchmarkCompare.js:REGRESSION_THRESHOLDS` 三场景 Rust 阈值改为等于或严于 JS 阈值（基于步骤 2 5 次稳定数据收敛后的最坏值 + 上限保险）：fixture rustP50 50→15/rustP95 80→20/rustStartup 100→50；large-20k rustP50 600→400/rustP95 800→500/rustStartup 100→50；nav-500-files rustBatch 5000→600/rustStartup 100→50。CI 运行路仍 `--no-threshold` 绕过（Linux runner 速度基线不同），本机 dev 不带 `--no-threshold` 跑会触发硬门禁。
   - 验收：本机 `npm.cmd run benchmark:compare -- --iterations 10` exit 0；fixture Rust p50 10.87<15、p95 15.70<20、startup 7.5<50；large-20k Rust p50 323<400、p95 335<500；nav Rust batch 387<600；`npm test` 全绿；`check:release:readiness --strict` 6 PASS+1 SKIP+0 FAIL

5. **切换 `package.json` 默认 backend 与版本号** — 把 `syntecMacro.analysisBackend` 默认值改为 `rust-wasm`，`enumDescriptions` 改为「Rust/Wasm analyzer（默认，v3.1.0 起生产后端；JS fallback 始终保留）」，`package.json`/`package-lock.json`/`README` 徽章/`CHANGELOG` 同步切到 `3.1.0`。
   - 入口文件：`package.json`、`package-lock.json`、`README.md`、`CHANGELOG.md`、`docs/3.x-Release-Runbook.md`
   - 验收：`npm.cmd run check:release -- --tag v3.1.0` PASS；`npm.cmd run check:release:readiness -- --strict` 全 PASS；`npm test` 全绿；`npm run smoke:installed` 验证扩展激活且 `rust-wasm` backend 实例化成功
   - 阻塞：步骤 2/3/4 全过 + `workerLifecycle.test.js` 9 项无新增 FAIL
   - 风险：切换后任何 `cargo clean` 清理 wasm 会导致 worker 永久 fallback（用户机器安装的是发布 VSIX 内 bundle 的 wasm，不依赖本地 cargo）；**默认 backend 切换必须经 user 决定**，agent 仅在三场景稳定达标后才可提交切换 PR
