## 1. v3.0.0 现状

- **默认分析后端**: `javascript`（与 v2.15.0 保持一致；理由见 §3）。
- **可选后端切换**: 设置 `syntecMacro.analysisBackend` 为
  - `rust-wasm-shadow`（双跑 JS + Rust/Wasm，差分日志，不影响最终诊断）
  - `rust-wasm`（主用 Rust/Wasm，加载/运行失败显式回退 JS）
- **Rust 诊断 parity**: 与 JS 67/67 稳定诊断 code 全 parity（含 ROBOT-MOV/MODBUS/STITCH-WEAVE/SIGNAL 5 批机器人规则组）。
- **Rust/Wasm 共享 AnalysisResult**: P0-A/B 130+10+17 等价（diagnostics / navigation / edits / profile / symbols）。
- **生产 Wasm asset**: `assets/rust-wasm/{manifest.json, syntec_core.wasm}` 经 `check:rust:wasm:asset` 全链校验（manifest 形状 + 字节长度 + SHA-256 + `WebAssembly.instantiate` + 必需 exports 子集），随 VSIX bundle 进分发。
- **Worker 注入**: `validatorWorker` 通过 `workerData.backend` 选 3 种 backend；`rustWasmWorkerAdapter` 支持 shadow/primary 模式 + `onFallback`/`onShadowMismatch`；运行中切换需重启 worker。
- **跨平台 CI**: `.github/workflows/rust-wasm.yml` 跑 `os: [ubuntu-latest, windows-latest]` 矩阵，跑完 smoke 后自动上传 perf-data，`cross-platform-alert` job 做跨平台告警。
- **发布前 self-check**: `.github/workflows/release.yml` 调用 `npm.cmd run check:release:readiness -- --strict` 把 §5 7 项门禁作为 release workflow 硬门禁。

## 3. 不变约束（永久有效）

以下规则在 Rust/Wasm backend 完全替代 JS backend 之前必须遵守：

1. **不得在没有 Rust 稳定收益时强行切换默认 backend 为 `rust-wasm`**——v3.0.0 实测 large-20k JS p50 422ms vs Rust 457ms 仍存微弱回归，因此默认仍是 `javascript`。下一步迭代如要切换，必须重新采集 fixture/large-20k/nav-500-files 三场景的 JS vs Rust 数据并证明 Rust 全场景 ≥ JS 后再发下一个 Minor release。
2. **不得删除 JavaScript fallback 或把失败转化为成功形状**——`onFallback` 必须显式记录 reason 字段（`manifest-missing`/`wasm-bytes-mismatch`/`wasm-sha-mismatch`/`exports-mismatch` 等），由 `workerLifecycle.test.js` 7 类边界集成测试守卫。
3. **不得把开发态 Wasm 复制进 VSIX 作为「先切换再补齐」**——bundled wasm 必经 `scripts/buildRustWasmAsset.js` 写入 manifest + SHA-256 + exports 子集断言才进 VSIX；`crates/syntec-core/target/` 等开发产物仍由 `.vscodeignore` 排除。
4. **不得把单一控制器、81RA 或 LTP 运行时现象泛化为所有 MACRO 文件**——LTP/机器人/Modbus 跨行状态、产品边界与运行时差异继续只记录证据不静态强制（参见 `src/robotValidator.js` 注释与 `docs/macro-knowledge/MACRO-LTP专项资料包.md`）。
5. **不得用 Rust benchmark 的理论优势替代真实 JavaScript/Rust 对比**——必须用 `npm.cmd run benchmark:compare` 实测 p50/p95/max/resultBytes/fallback 比例，套用 `REGRESSION_THRESHOLDS` 作回归硬门禁。
