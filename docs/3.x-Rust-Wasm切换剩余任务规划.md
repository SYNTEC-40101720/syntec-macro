# 3.x Rust/Wasm 切换剩余任务规划

## 1. 当前结论

当前发布版本仍为 **v2.15.0**，生产后端仍为 JavaScript。3.x 版本号、tag、Release 和 VSIX 发布必须等 Rust/Wasm 正式导入生产后端的全部门禁通过后再切换。

已完成的架构基础：

- `DocumentSnapshot`、`AnalysisRequest`、`AnalysisResult` 协议。
- JavaScript `analysisCore`、有界 `AnalysisHost`、Worker/Provider 收敛边界。
- Rust CLI/Wasm ABI、`RustWasmAdapter`、导航文件元数据适配。
- `AnalysisHost` 的 `javascript`/`rust-wasm` selector 和显式 JavaScript fallback。
- Rust/Wasm 与 JavaScript 的 51 类差分样例、完整回归和开发态基准。
- `RustWasmAdapter` 已位于 `src/` 并可随代码进入 VSIX，但尚未注册或默认启用。

当前仍是开发态的原因：

- Rust 诊断 code 已完成 JavaScript 全部稳定诊断集合的 67/67 parity 收口（详见 `docs/Rust诊断parity清单.md`）；P0-A.1 节点已合上。
- 调用与引用边界（GOTO 标签 / G65/G66/G66.1/M98/M198/M99/G67 调用返回 / `% 缺 %@MACRO` 文件头 warning）已 parity（P0-A.2 合上）；差分扩展到 130 类。
- P0-B 真实 request 传输已完成：Rust 端 `parse_analysis_request`/`analyze_request_json`/Wasm `syntec_core_analyze_request_json`/CLI `--request` 模式完整校验 `protocolVersion`/`document`/`profile`，`createRustWasmAdapter` 优先走新 ABI；差分扩展 P0-B 路径 130/130 等价。
- P0-B 第 2 项 symbols/navigation 已完成：Rust 端依据 `document.uri` 完整计算 `programEntryName`/`macroProgramName`，非 macro 文件返回 `navigation: null`，`compare:rust` 增加 navigation 差分环节 10/10 等价。P0-B 第 2 项 edits/TextEdit 已完成：`format_document` 完整移植 `formatter.js`，`AnalysisResult.edits` 整文档 `TextEdit` 17/17 等价；profile 协商透传非空 profile 与 JS 一致，未知 profile 当 generic 等价处理。**P0-B 第 2 项「完整结果」已合上**，进入 P0-C 生产 Wasm 资产与 Worker 接入。**P0-C 第 1 项 生产 Wasm 资产与加载器 已合上**：新增 `src/rustWasmAsset.js`（生产加载器，manifest + SHA-256 + 必需 exports + `WebAssembly.instantiate` 全链校验，每步失败抛带 `reason` 字段的 `RustWasmAssetError`），新增 `scripts/buildRustWasmAsset.js` 与 npm 脚本 `build:rust:wasm:asset`/`check:rust:wasm:asset`（`--check` 模式挂到 `npm test` 作为 CI 资产完整性门禁），新增 `assets/rust-wasm/manifest.json` 与 `syntec_core.wasm`（~312KB、SHA-256 `7b69e5dc...`）作为固定版本/target 的 wasm 资产物理载体；`scripts/probeRustWasm.js`/`scripts/benchmarkRustWasm.js` 改为默认走生产加载器 manifest 路径，`SYNTEC_RUST_WASM` 仅保留为开发逃逸端口；新增 `tests/rustWasmAsset.test.js` 16 项测试覆盖 8 类失败路径与成功路径，`npm test` 扩展到 312 项；资产目录经 `.vscodeignore` 仍不进 VSIX，Worker 注入与默认 backend 切换由 P0-C 第 2/3 项完成。
- LTP/机器人/Modbus 跨行状态、产品边界与运行时差异继续只记录证据不静态强制（参见 `src/robotValidator.js` 注释与 `MACRO-LTP专项资料包.md`）。
- Wasm 生产资产、加载器、完整平台构建矩阵和默认 Worker 接入尚未完成（P0-C）。

## 2. 剩余工作总览

### P0-A：完成分析能力 parity

依赖：无。完成前不得把 Rust/Wasm 设为默认后端。

1. **诊断 code 收口（已完成 67/67）**
   - 对照 `src/diagnosticCodes.js` 建立 Rust parity 清单（`docs/Rust诊断parity清单.md`）。
   - 全面补齐基础语法、G/M 调用、GOTO、函数、变量、无 code warning，以及机器人 TOOLCOR/ROBOT-MOV/ROBOT-MODBUS/ROBOT-STITCH-WEAVE/ROBOT-SIGNAL 五批共 24 个 `ROBOT_*` code 的等价实现。
   - dead code `SYNTEC_ROBOT_SWAITSIG_Q_RANGE` / `SYNTEC_ROBOT_SYNCOUT_Q_RANGE` / `SYNTEC_ROBOT_SKIPCOND_Q_RANGE` 仅在 `diagnosticActions.js` 注册但 JS/Rust 双端共同不 emit，parity 等价；若后续 JS 补登记 emit 入口，须同步迁移 Rust。
   - 三方差分差样例已扩到 115 类（`scripts/compareRustCore.js` 的 `CASES`），完成各自的 Rust 单测与 `RustWasmAdapter` 结构测试。所有已发布稳定诊断的 code、severity、UTF-16 range、message 顺序一致。
   - 目标：所有已发布稳定诊断的 code、severity、UTF-16 range、message 顺序一致——已达成。

2. **机器人/LTP/Modbus**
   - 按 `robotValidator.js` 的单行规则、跨行状态规则和 `G10 L1900/L1901` 规则分组迁移。
   - 保留 CNC、81RA、LTP、Script、APP Macro 的产品/载体边界，不将运行时或机型推断成通用静态错误。
   - 动态参数、表达式和未知 profile 保持不推断。
   - 状态：单行规则组（TOOLCOR/ROBOT-MOV/ROBOT-MODBUS/ROBOT-STITCH-WEAVE/ROBOT-SIGNAL）已全部 parity；跨行状态、运行时生命周期差异继续保留 JS 证据，不静态强制化为通用错误。

3. **调用与引用边界**
   - 完成 `G65/G66/G66.1/M98/M198/M99/G67` 的静态调用、返回边界和动态目标不跳转规则。
   - 完成 GOTO 标签收集、引用缺失、注释/字符串隔离和跨行位置回归。
   - 运行时生命周期、`WAIT()`、预解和 81RA/CNC 差异继续只记录证据，不静态强制化。
   - 补齐 `collectMetadata` 中的 `% 缺 %@MACRO` 文件头 warning（Rust 已在 `analyze_document` 主循环与文件末尾追加等价产出，使用 `push_diagnostic_without_code` 同步 codeless 形态）。
   - 目标：调用/返回/GOTO/% 文件头静态边界与 JS 等价——已达成（差分扩展到 130 类，含 `%` 缺头、GOTO 字符串/注释豁免、动态 GOTO 不跳转、M 码返回/取消等正反例）。

### P0-B：完成共享 `AnalysisResult` 合同

依赖：P0-A 的黄金样例稳定。

1. **真实 request 传输（已完成）**
   - Rust/Wasm 接收并校验完整 `AnalysisRequest`，包括 URI、文档版本、languageId、文本和 profile（Rust 端 `parse_analysis_request` + `analyze_request_json` + Wasm 导出 `syntec_core_analyze_request_json`；CLI `--request` 模式）。
   - 不能仅由 JavaScript 适配层事后补齐 document/profile（`createRustWasmAdapter` 已切到新 ABI 优先，缺失时显式 fallback 到 legacy 文本路径）。
   - 保留 protocol version、UTF-8、非法输入和错误结果的显式失败（`compare:rust` 加 P0-B 差分环节，130/130 类等价）。

2. **完整结果（已完成）**
   - diagnostics：可选 code/keyword、所有 severity、跨行 range（已 parity）。
   - symbols/navigation：完整文件入口、宏名、符号、调用、引用边界（programEntryName/macroProgramName/symbols/calls 已在 Rust 侧依据 `document.uri` 完整计算，差分 10/10 等价）—— ✅ 已完成。
   - edits：formatter 的 `TextEdit` 与 JavaScript 输出一致——`format_document` 完整移植 `formatter.js`，整文档 `TextEdit` 17/17 等价；profile 协商透传非空字符串与 JS 一致—— ✅ 已完成。
   - profile：generic 与未来产品 profile 的能力协商、未知 profile 的明确处理—— generic 已支持，未知 profile 当 generic 等价处理（与 JS `assertNonEmptyString` 一致），产品 profile 后续接入专属规则。

3. **差分门禁**
   - 黄金样例逐字段比较；不使用只比较数量或只比较 code 的代理指标。
   - Rust 失败时必须调用已注册的 `onFallback`，再回退 JavaScript；禁止静默成功。

### P0-C：生产 Wasm 资产与 Worker 接入

依赖：P0-A、P0-B。

1. 生成固定版本、固定 target 的 Wasm artifact，禁止把 `target/`、debug 文件或临时探针打包。
2. 增加生产加载器：
   - 资产路径和完整性校验。
   - Wasm 实例化、内存分配/释放和输出释放。
   - 初始化失败、超时、内存错误、JSON/协议错误均走显式 fallback。
3. 将 Worker 的 analyzer 注入 `AnalysisHost`：
   - 默认切换前支持 shadow/differential 模式。
   - 切换后 Rust 为主、JavaScript 为回退。
   - 记录 backend、fallback 原因和版本，不泄露源码或敏感路径。
4. 增加启动、重启、并发、取消、文档版本竞态和 fallback 集成测试。

### P1：跨平台与性能门禁

依赖：P0-C。

- Windows GNU/MSVC、wasm32、Node/VS Code 运行环境的可复现构建矩阵。
- CI 中执行 Wasm 构建、artifact 校验、Rust/JavaScript 差分和 VSIX 内容检查。
- 对真实 fixture、20,000 行档案、500 文件导航分别记录 JavaScript/Rust/Wasm：
  - 启动时间；
  - p50/p95 分析延迟；
  - JSON/内存占用；
  - 首次与重复查询；
  - fallback 比例。
- 没有稳定收益或出现回归时，保持 JavaScript 默认后端，不强行切换。

### P1：3.x 发布收口

依赖：P0-A、P0-B、P0-C、P1 门禁全部通过。

1. 将 `package.json`、`package-lock.json`、README、CHANGELOG 和交接文档切换到选定的 `3.x.x`。
2. 运行：

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run test:integration
npm.cmd run test:integration:navigation
npm.cmd run package
npm.cmd run smoke:installed
```

3. 校验 VSIX：
   - 生产 src/代码、grammar、snippet、文档和必要 Wasm 资产；
   - 不含 Rust target、debug artifact、测试 fixture、脚本探针或 session 文件。
4. 提交并推送 main，创建对应 `v3.x.x` tag。
5. 用 `npm.cmd run release:create -- v3.x.x` 创建 GitHub Release，上传 VSIX。
6. 核对 tag、Release、VSIX 下载地址、SHA-256、安装版本和默认 backend。

## 3. 不得提前做的事情

- 不得在 Rust parity、request/profile/TextEdit、跨平台构建和回滚门禁完成前升级 3.x 版本号。
- 不得把开发态 Wasm 文件复制进 VSIX 作为“先切换再补齐”。
- 不得删除 JavaScript fallback 或把失败转化为成功形状。
- 不得把单一控制器、81RA 或 LTP 运行时现象泛化为所有 MACRO 文件。
- 不得用 Rust benchmark 的理论优势替代真实 JavaScript/Rust 对比。

## 4. 每个迁移批次的固定验收

```powershell
git diff --check
npm.cmd test
npm.cmd run lint
npm.cmd run typecheck:analysis
npm.cmd run compare:rust
npm.cmd run probe:rust:wasm
npm.cmd run benchmark:rust:wasm -- --iterations 10
```

代码批次还必须更新对应的：

- `CHANGELOG.md` `[Unreleased]`；
- `MACRO知识与验证规划.md` 迭代记录；
- `开发交接说明.md` 当前入口；
- Rust 单测、JavaScript 单测和三方差分样例；
- 若涉及诊断规则，能力矩阵、语法手册和生成诊断文档。

## 5. 完成定义

只有以下条件全部满足，才允许将版本从 2.x 切换到 3.x：

1. Rust/Wasm 完整 `AnalysisResult` parity；
2. 所有已发布稳定诊断和核心导航/格式化行为 parity；
3. 生产 Wasm 资产、加载器、Worker 接入和显式 JavaScript fallback；
4. Windows GNU/MSVC、Wasm 和 CI 构建矩阵可复现；
5. 真实性能、内存、启动和 fallback 数据达标；
6. VS Code 集成、VSIX 内容、隔离安装和回滚验证通过；
7. GitHub tag、Release、VSIX 资产和校验值一致。
