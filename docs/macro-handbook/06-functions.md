### 9.3 单位转换函数

状态：已确认 / 待落地

| 函数 | 说明 | 范例 |
| --- | --- | --- |
| `STD(value, unit)` | 将整数值转换为系统输入单位 | `#10 := STD(100, #1600);` |
| `STDAX(value, axis)` | 将整数值转为对应轴向标准单位 | `#24 := STDAX(#24, X);` |

规则：

- 输入数值已为 Double 时，不进行转换。
- 若 `Pr3241=1`，仅将整数型别转为小数点型态，不做数值转换。
- `STD` 第二引数 `#1600` 为线性轴最小输入单位（LIU），代表 `Pr17` 控制精度下的一个最小刻度，也是官方示例最常用的第二引数。
- 对长度或角度的整数引数，官方 MACRO 开发应用手册建议在运算前使用 `STD` 标准化，避免控制精度导致的单位歧义。
- `Pr17`、`Pr3241`、单位制与可用轴均属控制器配置，静态分析不能可靠给出结果或错误。
- `STDAX` 轴名推荐裸轴名，不使用字符串；`STDAX(#1, "X")` 可先做 warning。

### 9.5 系统诊断函数

状态：已确认 / 待落地

| 函数 | 说明 | 范例 | 有效版本 |
| --- | --- | --- | --- |
| `SYSDATA(diagNo)` | 读取系统诊断变量 | `WAIT(); #1 := SYSDATA(336);` | 10.118.23U、10.118.28H、10.118.33 |
| `DRVDATA(station, varNo)` | 读取驱动器状态变量 | `#1 := DRVDATA(1000, 3366);`、`#2 := DRVDATA(1003, "D61h");` | 10.118.23U、10.118.28I、10.118.34 |

规则：

- `DRVDATA` 变量号码支援 10 进位整数与 16 进位字符串，例如 `"D61h"`；十六进制字符串需符合 `"xxxh"` 格式，`x` 仅能为 `0~F` 且结尾 `h` 为小写，否则触发 `COR-023` 句法错误。
- 无对应驱动器时 `DRVDATA` 回传 VACANT；不支援的状态变量触发 `COR-016`；格式错误触发 `COR-023`；开机后资料就绪前调用亦可能触发 `COR-016`。
- 使用 `SYSDATA` / `DRVDATA` 前建议加 `WAIT()`，确保取得当前最新数值。
- `DRVDATA` 每次呼叫约 0.1~0.2 秒。
- 站号无对应驱动器时，`DRVDATA` 回传 VACANT。
- 开机一分钟内呼叫 `DRVDATA` 可能触发 `COR-016`。

#### 9.5.1 M30 与 Pr732 计数联动

状态：部分待确认

来源：CF [PLC介面说明](https://syntecclub.atlassian.net/wiki/spaces/TechManual/pages/44105796/PLC)（§R615 MST 请求旗标）与 [控制器参数总表 §Pr732](https://syntecclub.atlassian.net/wiki/spaces/TechManual/pages/44105816)（侧面提到与 M30 计数联动）证实存在「M30 → PLC 计数上报」路径。

语义（已证实部分）：

- `M30` 作为主程序末节指令，实务上同时承担两件事—— 生成 PLC 主轴/M 码完成旗标 (R615 bit) 与计数主程序完成 次 数。
- `Pr732` 划定多轴群场景下与主轴系统轴群绑定的 MST 请求旗标的取值轴群位，这与 `R615.8 ~ R615.11` 多轴群辅助旗标联动 (见 `02-variables.md §2.10.1`)。
- M30 下达后 PLC 可听 R615 上升沿推出计数、上报不了的位置错误 / 实际计数 1 计数荔加在 `#1108` 之类的模态变量上。

未证实部分（标 partial）：

- CF 公开页面未列出 `Pr732` 与计数 `R contar` / `M30` 的详细位元拆位公式。分段拆解 / 轴群选择性 M30 计数的具体 PLC 逻辑 需要实机或《控制器参数总表》PDF 二次确认。
- 第一手官方未明说 `M30` 是否与未开始的轴群 MST 计数同步联加，是否存在各轴群不同计数动作。需以实机 PLC 调试为准。

应用场景：

- 多轴群机床跨 PLC 资源场景中需记录「M30 发生次数」，以 `M30;` 作为一轴群完成计数循环点，由 PLC 联加到概数屯 中心 Status Reg 01 (R 压合本机区域使用人员表使用。这个场景需以 R615 上升沿触发外部事件 (见 §2.10.1)；写入后需 `WAIT()` 等待原点 / 锁定完成。

插件策略：

- 本节为「资料阻塞」部分待确认；插件不做强静态诊断，仅提供 hover / snippet 提示 M30 可联动 `Pr732` / `R615` 上报计数。
- 在使用 `M30` 时 提示同段加工档未 加 `WAIT()` 指令 可 能在 PLC 在听计数前被反覆预设，需提示 user 加入 `WAIT()`。

#### 9.5.2 Modbus 32-bit R 寄存器拆位辅助

状态：已确认 / 部分现场需二次确认

来源 † ：[新代控制器 Modbus 通讯SOP](https://syntecclub.atlassian.net/wiki/spaces/~C1720/pages/483251200/Modbus+SOP+Macro+PLC)（个人空间笔记），与 `05-robot.md §8.4.7.1` 互补。

公式：

- 标准 Modbus 读 / 写 32-bit 整数需占 2 个 16-bit R 寄存器。
- `Rn` 存高位、`Rn+1` 存低位时：`32-bit 整数值 = Rn * 65536 + Rn+1`。
- 反序存偏存式（低位在前、高位在后）需 PLC 侧定义决定，不在宏编程层强制。
- 若读取 Float32 (Modbus 类型 IEEE 754 Float)，需使用位元拆位重组 - 这个拆解主要在 PLC 开发环境部分或低阶逻辑解读，不能在宏端简单拼加。

辅助代码示例：

```iecst
// 读 high = R1000, low = R1001
WAIT();
#1 := @14000 * 65536 + @14001;
// 写 32-bit 数值 70000 -> high = 1, low = 446465
#10 := 70000;
#11 := #10 / 65536;   // high
#12 := #10 - #11 * 65536; // low
G10 L1000 P14000 R#11;  // 写 high
G10 L1000 P14001 R#12;  // 写 low
```

辅助函数表：

| 场景 | 提示动作 |
|---|---|
| 读多笔 → 拼为 32-bit 整数 | 先 `WAIT()` 挡预解，后 `#1 := @RX * 65536 + @RY` |
| 写 32-bit 整数 → 拆为 2 笔 16-bit | 拆位后 `G10 L1000 PRA R#high` + `G10 L1000 PRB R#low` |
| 读 Float32 | 不在宏端拼加，交 PLC 层或调用动作函数 |

插件策略：

- 不识别 `@Rx * 65536 + @Ry` 表达式为「32-bit 重组」作特定诊断，这种拆位属社区型做法，不是控制器官方提供抳械函数。
- 如 user 以 `@Rx * 65536 + @Ry` 出现偏存反序式（高位在 after 低位在 before）， 插件 不会加 区间 警告提示，反序说明依赖 PLC 侧定义。

### 9.8 Cycle 数据库函数

状态：已确认 / 待落地

| 函数 | 说明 | 回传值 |
| --- | --- | --- |
| `DBOPEN("file")` | 开启既有 Cycle 档案 | 1~N 为资料笔数；0 失败 |
| `DBNEW("file")` | 新增空白 Cycle 档案 | 1 成功；0/-1/-2 失败 |
| `DBLOAD(index)` | 读取第 index 笔资料 | 1 成功；0 失败 |
| `DBSAVE(index)` | 储存覆盖第 index 笔 | 1 成功；0 失败 |
| `DBINSERT(index, "name")` | 插入新资料 | 1 成功；0/-1/-2/-3 失败 |
| `DBDELETE(index)` | 删除第 index 笔资料 | 1 成功；0/-1/-2 失败 |

规则：

- `DBNEW`、`DBINSERT`、`DBDELETE` 有效版本为 10.118.56L、10.118.60F、10.118.66 起。
- `DBSAVE` 有效版本为 10.118.39 起；需先开档并已成功 `DBLOAD` 或 `DBINSERT`。
- 所有 DB 函数不支援图形模拟，模拟时固定回传 0。
- `DBOPEN` 与 `DBNEW` 同时只能开启一个 Cycle 档案；后调用会取代当前会话中的档。
- `DBLOAD(index)` 会将「目前 Cycle name」设为该笔资料的 name；紧接着 `DBINSERT(index, "name")` 会将「目前 Cycle name」覆盖为引数 name。后续令覆盖前令是官方定义的正常运行时行为，不应作为静态错误。
- `DBDELETE(index)` 返回码含义：`1`=成功、`0`=失败、`-1`=超出索引范围、`-2`=未开档。静态不提升 `-1`/`-2` 为错误，因两者依赖运行时索引与开档状态。
- 不根据静态代码推断档案是否存在、索引是否在运行时范围内，避免工作区缺少真实 Cycle 档时造成误报。

### 9.11 流程控制函数

状态：已确认

| 函数 | 说明 | 范例 |
| --- | --- | --- |
| `WAIT()` | 停止预解，直到 WAIT 前的 G/M 码执行完毕 | `G01 X100.; WAIT(); #1 := #1321;` |
| `SLEEP()` | 暂时放弃此次宏程序执行权，避免循环锁死人机 | `WHILE @1=0 DO SLEEP(); END_WHILE;` |

规则：

- `M98`、`M99`、`M198` 不受 `WAIT()` 影响。
- `SLEEP` 适合用于循环中让出执行权。

### 9.12 图形模拟函数

状态：已确认

| 函数 | 说明 | 范例 |
| --- | --- | --- |
| `SETDRAW(color)` | 设定图形模拟路径颜色 | `SETDRAW(12);` |
| `SETDRAW(color, fill, radius)` | 设定路径颜色、填充颜色、刀具半径 | `#3 := SETDRAW(#1, #2, #18);` |
| `DRAWHOLE()` | 在当前位置画一个圆，仅图形模拟 | `DRAWHOLE();` |

常用 BGR 颜色：

| 代码 | 颜色 | BGR 值 |
| --- | --- | --- |
| `0` | 黑 | `0` |
| `1` | 暗蓝 | `8388608` |
| `2` | 暗绿 | `32768` |
| `4` | 暗红 | `128` |
| `9` | 亮蓝 | `16711680` |
| `10` | 亮绿 | `65280` |
| `12` | 亮红 | `255` |
| `14` | 亮黄 | `65535` |
| `15` | 白 | `16777215` |

BGR 码与 RGB 码的 B 和 R 顺序相反。例如 RGB 红色 `0xFF0000` 对应 BGR 值 `0x0000FF = 255`。

`SETDRAW` 同时影响后续路径与 `DRAWHOLE` 的颜色。若圆形与后续路径需要不同颜色，可将 `SETDRAW` 回传的原路径颜色存入变量，在 `DRAWHOLE()` 后再次调用 `SETDRAW` 恢复：

```iecst
#orig := SETDRAW(0x0000FF);  // 设为红色，原色被暂存
DRAWHOLE();
SETDRAW(#orig);              // 恢复原路径颜色
```

`DRAWHOLE` 在当前模拟位置画圆，并使用当前 `SETDRAW` 的颜色与刀具半径；它是图形模拟功能，静态分析不应当作实际加工动作。颜色值、填充、刀具半径、当前位置与模拟器渲染均为运行时上下文，插件不新增范围或调用顺序诊断。

### 9.13 安全验证函数

状态：已确认 / 部分版本差异

| 函数 | 说明 | 回传 | 有效版本 |
| --- | --- | --- | --- |
| `CHKMN("code")` | 检查机械厂代码 | 1 一致，0 不符 | 10.116.6A |
| `CHKSN("sn")` | 检查控制器序号 | 1 一致，0 不符 | 10.116.6A |
| `CHKMT("type")` | 检查机床属性 | 1 一致，0 不符 | 10.116.6A |
| `CHKMI("model")` | 检查控制器机型 | 1 一致，0 不符 | 10.116.6A |
| `CHKINF(cat, "code")` | 统一检查函数 | 1 一致，0 不符 | 10.118.22M、10.118.28B、10.118.30 |

`CHKINF` 类别：

| 类别 | 内容 | 等同函数 |
| --- | --- | --- |
| `1` | 机械厂代码 | `CHKMN` |
| `2` | 序号 | `CHKSN` |
| `3` | 机床属性 | `CHKMT` |
| `4` | 机型 | `CHKMI` |
| `5` | 专机代码 | - |

各函数语义与应用场景：

- `CHKMN("code")`：宏代码内写入机械厂代码字符串，控制器在 CycleStart 前比对系统注册的机械厂代码；一致回传 1，不一致回传 0。常用于把宏程序绑定到具体机械厂出货机型，避免跨机械厂误用。
- `CHKSN("sn")`：检查控制器序号，常用于单机授权宏，避免跨机台拷贝运行。
- `CHKMT("type")`：检查机床属性（如铣床/车床/激光/机器人），避免控制器将不适用机型的工艺宏档执行。
- `CHKMI("model")`：检查控制器机型，常用于区分 81RA / 22MA / 新旧软体版本分支执行不同工艺路径。
- `CHKINF(cat, "code")`：统一入口，避免宏代码中央堆 `IF CHKMN() = 1 OR CHKMT() = 2` 等多判语句；行为与上述专线函数等价，常用于加密包装宏（见 [MACRO开发应用手册 §附录-MACRO XML 资料应用](https://syntecclub.atlassian.net/wiki/spaces/TechManual/pages/44106050/MACRO)）。

与 MACRO XML 资料应用的关系（CF [44106050 §附录] 证实）：

- 官方 MACRO XML 资料应用方案允许通过 Schema 文件描述宏加密、宏参数与工艺资料；运行时由 `DBOPEN`/`DBLOAD` 等资料库函数配合 schema 解析。
- 加密包装宏常先执行 `CHKMN`/`CHKSN`/`CHKMT` 系列返回值判断再加载 XML 资料包；若校验失败宏程序即 `M99` 立即返回，避免后续 `DBLOAD` 拿到本机型不该使用的资料包。
- 具体加密函数（如内部 `CHKMN`、`CHKSN`、`CHKMT` 真值比对存储在控制器哪个非易失区）对开发者透明，仅在 [新代MACRO教学(六)](https://syntecclub.atlassian.net/wiki/spaces/EL/pages/472459082/2026-MACRO) 提到「加密工具」概念。本手册只确认函数签名与对外语义，不写存储区实现细节。

插件策略：

- 这些函数返回值为 0/1，不应直接参与四则运算；静态诊断可对 `#1 := CHKMN("abc") * 100` 等场景给出 warning 提示语义可能非用户预期。
- 字符串常量引数若包含非 ASCII 字符（如中文字符），CF 页面列出可能导致字符串比对失败，插件可加 hint。
