## 0. 状态标记

| 标记 | 含义 | 插件策略 |
| --- | --- | --- |
| 已确认 | 已由官方文档、实机或项目规则确认 | 可用于 hover、snippet、validator、测试 |
| 兼容不推荐 | 控制器可能接受，但不建议新代码生成 | validator warning |
| 不支持 | 控制器不支持或项目已确认不可用 | validator error |
| 待确认 | 资料不足或版本差异未确认 | 暂不做强诊断，写入待确认清单 |

## 1. 基础文件格式

### 1.1 MACRO 格式判定

状态：已确认

```iecst
%@MACRO
```

规则：

- MACRO 格式由文件内容决定，而非后缀名决定。
- 文件第一行为 `%@MACRO` 时，控制器核心按 MACRO 格式处理。
- 若无 `%@MACRO`，控制器核心按 ISO 格式处理。
- 若文件首个有效行是 `%` 而不是 `%@MACRO`，插件提示 warning：该文件可能被视为 ISO 格式。

### 1.2 文件后缀与加工档选择

状态：已确认

系统人机默认可选取的加工档后缀来自 `MMIConfig_Customer.xml` 的 Filter 配置。默认包含：

| 后缀 | 说明 |
| --- | --- |
| 无后缀 | 扩充 G 码与 O 码副程序常用形式 |
| `.nc` | 常用数控加工档 |
| `.cnc` | CNC 加工档 |
| `.tap` | 常见 CAM 输出 |
| `.prt` | 零件程序 |
| `.mpf` | 西门子风格主程序 |
| `.ptp` | 点到点加工程序 |
| `.pim` `.anc` `.bj` `.edit` `.demo` | 人机默认 Filter 可选后缀 |

默认 Filter：

```xml
<Filter>**.edit;**.demo;**.bj;**.anc;**.pim;**.tap;**.prt;**.mpf;**.ptp;**.cnc;**.nc;**.</Filter>
```

说明：

- 最后的 `**.` 代表允许选取无后缀文件。
- Filter 可由机械厂自行修改。
- 插件自动关联常见加工档后缀，但 `.txt` 不默认关联，避免抢占普通文本文件；`.txt` 若首行为 `%@MACRO` 仍可通过首行识别或手动切换语言处理。

### 1.3 扩充 G 码宏程序命名

状态：已确认

规则：

- 命名范围：`G200` ~ `G999`。
- 文件名不可以带后缀名。
- 支持 4 字命名与 6 字命名。

| 调用语法 | 文件名 |
| --- | --- |
| `G200` | `G0200` |
| `G200.1` | `G200001` |
| `G200.10` | `G200010` |

示例：

```text
正确：G0200
错误：G0200.NC
错误：G0200.TXT
```

### 1.4 O 码副程序命名

状态：已确认

规则：

- O 码副程序命名为 `O` + 数字，例如 `O8000`、`O0010`。
- O 码副程序同样使用无后缀文件名。
- 副程序呼叫时按文档管理的资料夹设定查找。

### 1.5 文件存放路径与优先级

状态：已确认

| 位置 | 路径 | 说明 |
| --- | --- | --- |
| 加工档案 | `DiskA:\OpenCNC\NCFILES` | 一般加工程序；可在人机编辑 |
| 系统 MACRO | `DiskC:\OpenCNC\MACRO` | 系统级宏程序；人机中不可编辑 |
| 模拟器 | `DiskC\OpenCNC\MACRO` | 模拟器环境 |

查找优先级：

```text
NCFILES > MACRO
```

两处都有同名文件时，NCFILES 优先。

### 1.6 Macro 转换工具输入格式

状态：已确认

规则：

- 转换工具输入文件可为 `.txt` 或 `.nc`。
- 编码可为 UTF-8 或 BIG5/CP950。
- 这是转换工具输入格式，不代表控制器核心以 `.txt` 后缀判定 MACRO 格式。

### 1.7 插件识别策略

状态：已确认

| 场景 | 插件策略 |
| --- | --- |
| 常见加工档后缀 | 自动关联 `.nc`、`.cnc`、`.tap`、`.prt`、`.mpf`、`.ptp`、`.pim`、`.anc`、`.bj`、`.edit`、`.demo` |
| 任意首行为 `%@MACRO` 的文件 | 通过 firstLine 规则识别为 `syntec-macro` |
| `.txt` 文件 | 不默认关联，避免影响普通文本；可通过 `%@MACRO` 或手动切换语言识别 |
| `.macro` / `.scp` / `.G` | 不默认关联 |
| 无后缀扩充 G 码 / O 码 | 依首行 `%@MACRO` 识别；跳转搜索优先查无后缀文件 |

### 1.8 注释

状态：已确认

```iecst
// 单行注释
(* 多行块注释 *)
```

规则：

- 注释中的关键字、变量、GOTO 目标不参与诊断。
- 中文可出现在注释中。

### 1.9 字符集

状态：已确认 / 部分版本差异

规则：

- 代码区只允许英文/ASCII 字符。
- 中文可出现在注释和字符串中。
- 中文标点若出现在代码区，报 error。
- MACRO/PLC 非英文注解（如简体中文、繁体中文）在切换语系后可能出现异常；源文件应保持 UTF-8 编码（来源 [控制器多国语系使用说明手册](https://syntecclub.atlassian.net/wiki/spaces/TechManual/pages/44105843)）。
- UTF-8 是控制器官方推荐用于规避该异常的编码；其他编码如 BIG5/CP950 仅作为历史转换工具读取权宜，不建议长期储存。

来源证实：CF [44105843 控制器多国语系使用说明手册]（2026-05-15 版）说明「MACRO/PLC 非英文注解切换语系后异常」属于控制器已知行为，UTF-8 编码是规避该异常的官方推荐。

插件策略：

- 文件解析时优先按 UTF-8 解码；不能解码时回退 BIG5/CP950 作为转换工具读取入口（与 §1.7 插件识别策略一致）。
- 静态诊断不强行校验非英文注解是否触发异常；运行时语系切换属控制器行为，超出静态诊断范围。

### 1.10 MACRO 读取/处理流程

状态：已确认 / 部分版本差异

MACRO 执行涉及三个阶段：档案识别、核心解译、运动执行。控制器核心会以预解方式提前解译 MACRO 内容，因此变量运算通常会超前于实际 G/M 码运动执行。

```text
档案识别 -> 核心解译/预解 -> 运动执行
首行 %@MACRO  逐行解译与建表  G/M 码实际驱动轴向运动
```

格式识别：

| 条件 | 处理方式 |
| --- | --- |
| 第一行为 `%@MACRO` | 视为 MACRO 格式，支援完整 MACRO 语法 |
| 第一行不含 `@MACRO` | 视为 ISO 格式，不支援 MACRO 语法 |

档案查找路径：

| 优先级 | 路径 | 说明 |
| --- | --- | --- |
| 1 | `DiskA:\OpenCNC\NCFILES` | 一般加工档案资料夹 |
| 2 | `DiskC:\OpenCNC\MACRO` | 系统 MACRO 资料夹 |
| 3 | `DiskC:\OpenCNC\Res\*.res` | 打包的 res 文件内 |

若 NCFILES 与 MACRO 资料夹内存在同名文件，NCFILES 优先。APP Macro 独立路径为 `DiskC:\app\%AppName%\bin\Macro\`，只有该路径下的 Macro 才能存取 AR/MAR。

单节解译顺序：

| 顺序 | 内容 | 说明 |
| --- | --- | --- |
| 1 | 模态 G 码 / 扩充 G 码宏程序 | 例如 `G15`、`G17`、`G70`、`G73`、`G84` |
| 2 | M 码宏程序 / T 码宏程序 | 已登录 M 码宏程序、`Pr3215=2` T 码宏程序 |
| 3 | S 码 | 主轴转速 |
| 4 | F 码 | 进给速度 |
| 5 | H 码 | 刀具补偿功能 |
| 6 | D 码 | 刀具补偿功能 |
| 7 | T 码 | 刀具选择，非宏程序时作为辅助码 |
| 8 | M 码 | 辅助码，非宏程序时作为辅助码 |
| 9 | B 码 | B 轴命令 |
| 10 | 插值 G 码 / 功能 G 码 | 例如 `G0`、`G1`、`G4`、`G51`、`G68` |

同一行若同时存在 G 码宏程序与 M 码宏程序，核心会先解译 G 码宏程序。若 G 码宏程序读取并占用了轴向引数，则同一单节中后续 M 码宏程序或插值 G 码可能读取不到这些引数。

预解机制：

- 变量运算在解译阶段即时完成。
- G/M 码运动在执行阶段才实际动作。
- 因此变量读取可能早于运动完成，读取机械座标或状态时容易取得旧值。
- `WAIT()` 可阻止预解继续进行，直到 WAIT 前的 G/M 码执行完毕。
- `M98`、`M99`、`M198` 不受 `WAIT()` 影响，`WAIT()` 不会等待它们执行完毕。

```iecst
%@MACRO
G01 X100. F500;
WAIT();
#1 := #1321;
G01 X(#1 + 50.);
M30;
```

流程跳跃资讯表：

- 控制器处理 `IF`、`CASE`、`WHILE`、`FOR`、`REPEAT` 等范围语法时，需要建立流程跳跃资讯表。
- 目前采用动态产生方式，边解译边建表。
- 动态建表可直接 CycleStart，不需等待完整扫描。
- 大档案中语法区间过大时，跨页跳转可能造成轴向降速。

大档案处理：

| 项目 | 规格 |
| --- | --- |
| 60KB 以内 | 完整支援所有语法 |
| 60KB 以上，10.120.32 及以后 | 支援 `IF` / `CASE` / `REPEAT` / `FOR` / `WHILE` 跨页 |
| 60KB 以上，10.120.32 之前 | 不支援有范围区间语法，可能触发 `COR-204` 档案太大 |

相关诊断变量（以 [控制器诊断变数](https://syntecclub.atlassian.net/wiki/spaces/TechManual/pages/44106009) 与 [MACRO开发应用手册](https://syntecclub.atlassian.net/wiki/spaces/TechManual/pages/44106050/MACRO) 证实）：

| 诊断变量 | 说明 | CF 证实状态 |
| --- | --- | --- |
| `D320` | 解译总线单节数，反映解译器缓冲深度；加工开始时上升，完成时下降。 | CF 已证实 |
| `D324` | 已规划块数（含义紧邻 D320，用于与 D376 串联判断降速）；CF 示意「D320 先消耗到0，则 D324 消耗到0，D376 加1」。 | CF 已证实（与D376 绑定） |
| `D376` | 运动规划减速次数；D320 消耗到 0 且 D324 消耗到 0 后 D376 加 1，表示当前加工段写入超过解译能力，语法区间过大时可见持续上升。 | CF 已证实 |
| `D388` | Script executor 执行的平均时间，单位 us（micro-second）；若持续累加，注意常驻运算程序内是否存在无穷回圈。Linux 系统上报该值；CF 未列出该诊断号适用的最低控制器版本。 | CF 已证实 |

CF 未公开页面直接证实的诊断号：

| 诊断号 | 仓库原标注 | CF 状态 |
| --- | --- | --- |
| `D978` / `D979` | MacroExecutor 执行实际时间（平均/最大），单位 us | CF 未证实；未在《控制器诊断变数》找出这二号的独立条目，初始资料可能编号有误或属于内部版本变量；待实机或控制器内部规格复核。 |
| `D994` / `D995` | Script Executor 执行时间（平均/最大），Linux 支援 | CF 未证实；若有 Script executor 执行时间需求，可优先使用已证实的 D388（平均时间），最大值对应变量在 CF 未列出。 |

NetPLC 相关诊断（[NetPLC 使用说明](https://syntecclub.atlassian.net/wiki/spaces/TechManual/pages/44106337/NetPLC) 证实）：

| 诊断号 | 说明 | 起始版本 |
| --- | --- | --- |
| `D932` | NetPLC 同步 R 寄存器的平均总时间（同步时间 + Pr3239 通讯间隔），单位 ms。 | 10.118.86K 、 10.120.16K 、 10.120.24B 、 10.120.27 及之后版本。 |
| `D933` | NetPLC 同步 R 寄存器的最大总时间。 | 同上 |

效能诊断原则（CF 证实）：

- 加工中若持续出现 D320 消耗到0 → D324 消耗到0 → D376 加 1 的循环，表示当前加工段超过解译器的解译负载，典型原因是语法区间过大、大档案跨页 IF/CASE/REPEAT/FOR/WHILE 等过深区段，可考虑拆分或缩小区间。
- D388 持续累加时，检查常驻 Script 是否存在无穷回圈。
- 仓库原标注的 `D978` / `D979` 大于 4 倍 PLC 扫描时间的手册原则，缺乏 CF 正式页面背书，在取得实机证据前不作为诊断依据。诊断号清单直接查 [控制器诊断变数](https://syntecclub.atlassian.net/wiki/spaces/TechManual/pages/44106009)。

宏程序呼叫流程：

1. 父程序呼叫扩充 G 码、G65、M 码宏程序或副程序。
2. 控制器依路径优先级查找目标文件。
3. 对宏程序呼叫创建独立 `#1` ~ `#400` 区域变量空间；副程序呼叫依规则继承主程序变量空间。
4. 将引数写入对应 `#1` ~ `#26`，扩充引数使用 `GETARG` 读取。
5. 执行目标 MACRO。
6. `M99` 返回并回收独立区域变量空间。

`#1000` 插值模式：

- `#1000` 记录当前插值模式。
- MACRO 返回后，最后插值模式会影响父程序后续单节的执行模式。
- 遇到 `G00`、`G01`、`G02`、`G03`、`G31`、`G33` 或 `#1000` 内容变动时，`#1000` 会被自动改写。
- 若宏程序将 `#1000` 设为自身扩充 G 码号，父程序后续无显式插值模式的单节可能再次触发该宏程序。

实务建议：

- 读取运动后的座标或状态前，先加入 `WAIT()`。
- MACRO 内改变 `G90/G91` 时，进入时备份 `#1004`，离开前用 `G#10` 还原。
- 避免在 MACRO 中任意改变座标系统，例如 `G92`、`G54`、`G52`，以免影响父程序或图形模拟。
- MACRO 结尾应使用 `M99` 返回父程序。
- 长度或角度引数运算前建议使用 `STD` 标准化。
- 跨 MACRO 资料交换优先考虑模态变量 `#2001` ~ `#3100`，减少公用变量资源占用。
- 循环中加入 `SLEEP()` 可降低无穷循环锁死人机的风险。
