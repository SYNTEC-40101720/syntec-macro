## 1. 背景

终端大厂(杨达鑫、富士康、长盈)的宏程序(刀具寿命、刻字、探头)已习惯 FANUC、三菱语法与变量, 转换到新代修改成本高. 华领终端几乎全是三菱使用者, 需求新代宏程序语法和变量与三菱一致, 以性价比替代三菱系统.

新代现状: 提供 [FANUC Macro 语法转换小工具] 与 [AI Macro 转换小工具] 两个工具, 但部分语法不支援, 且转换结果与一线现场已验证程序存在差异(尤其多通道/轴群维度与探头应用).

## 2. 发那科 → 新代 语法差异表

来源: Confluence 27355508.

| 维度 | 新代 | 发那科 | 说明 |
| --- | --- | --- | --- |
| 开头格式 | `@%MACRO` (或 `%@MACRO`) | 程序名字 | 新代首句为宏头 |
| 行尾标点 | 每句加分号 `;` | 句后无标点 | |
| 括号 | `()` | `[]` | 新代用小括号, 发那科用中括号 |
| 赋值 | `:=` | `=` | |
| 比较符号 | `<` `>` `=` `<>` | `EQ` `NE` `GT` `GE` `LT` `LE` | |
| 变量表 | 新代变量表 | 发那科变量表 | 定义不同 |
| 时间/日期变量 | 新代 | 发那科 | 不同 |
| WHILE | `WHILE <cond> DO ... END_WHILE;` | `WHILE <cond> DO ... END<语句>` | 新代需 `END_WHILE` |
| IF | `IF <cond> THEN ... ELSE IF ... END_IF;` | `IF <cond> GOTO <程序号>` | 新代需 `END_IF`, 发那科用 `GOTO` |
| 取整函数 | 新代上下取整 | 发那科上下取整 | 不同 |
| 档案传输 | U盘 | 超级链接 | 发那科开头/结尾可能有 `%`, 不影响 |
| 注释 | `//` 与 `(* *)` | `()` | |
| G 码 | **TYPE A** (与 Pr3201 设定无关) | — | 新代宏程序内 G 码固定 TYPE A |

> 插件诊断覆盖: `SYNTEC_UNSUPPORTED_EQUALITY_OPERATOR`(`=`→`=`)、`SYNTEC_UNSUPPORTED_INEQUALITY_OPERATOR`(`!=`→`<>`)、`SYNTEC_UNSUPPORTED_FANUC_COMPARISON`(`EQ/NE/GT/GE/LT/LE`→`= / <> / > / >= / < / <=`)、`SYNTEC_UNSUPPORTED_DIV`(`DIV`→`/`)、`SYNTEC_UNSUPPORTED_PERCENT`(`%`→`MOD`)、`SYNTEC_ASSIGNMENT_STYLE_EQUALS`(`=`→`:=`)、`SYNTEC_UNSUPPORTED_ELSIF`(`ELSIF`→`ELSEIF`)、`SYNTEC_UNSUPPORTED_DEFAULT`(`DEFAULT`→`ELSE`).

## 3. 三菱多通道变量共享机制

来源: Confluence 837721919 §同业研究.

三菱通过参数控制跨路径(通道)变量共享:

| 参数号 | 功能 | 设置示例 |
| --- | --- | --- |
| No.1052 | 路径公共变量总使能 | 1 = 开启跨路径共享; 0 = 关闭(默认) |
| No.1303 | `#100~#199` 共享数量 | 填 N → `#100~#(99+N)` 全路径通用, `#(100+N)~#199` 各路径独立 |
| No.1304 | `#500~#999` 共享数量 | 填 N → `#500~#(499+N)` 全路径通用, `#(500+N)~#999` 各路径独立 |

多通道配置举例:
- 全部 `#100~#199` 互通 → `1303=100`
- 仅 `#500~#550` 互通 → `1304=51`
- `#100~#150` 互通, `#500` 全独立 → `1303=51, 1304=0`

> 建议规格(来源 837721919 §建议规格): Macro 资料夹分 `MacroS`(新代 Macro) 与 `MacroM`(三菱 Macro); 诊断变量提供新代/三菱切换 (`@`共享变量 / `#`程式变量 新代/三菱切换); Ncfiles 透过参数决定格式. 此为产品长期规格, 当前插件不实现切换, 仅检测不兼容语法.

## 4. 一线程序转换差异(探头应用)

来源: Confluence 849614054. 对比 V1.3 转换小工具输出与一线现场已验证程序的差异, 重点是探头相关 Macro 程序在多通道/轴群维度的实际需求.

### 4.1 已知转换问题

| 问题 | 转换工具输出 | 一线现场使用 | 转换前(三菱) |
| --- | --- | --- | --- |
| **G31 跳脱转换** | `G231` (不带 Q 引数) | `G31 ... Q(105+(#1508-1)*1)` | `G31 Y[#1-#32] F#119` |
| **#1361 系统变量** | `@1361` (单通道) | `#[1361+(#1508-1)*3]` (多通道轴群偏移) | `#5063` |
| **刀长补偿变量** | `#11000+#20` (单通道) | `#[31300+(#1508-1)*300+#20]` (多通道) | `#[2000+#20]` |
| **POPEN/DPRNT/PCLOSE** | 报「不支持」 | `OPEN` / `PRINT` / `CLOSE` | `POPEN` / `DPRNT` / `PCLOSE` |
| **刀长磨损变量** | `#[11000+#20]` | `#[35300+(#1508-1)*300+#20]` | `#[2000+#20]` |

### 4.2 关键差异说明

1. **G31 → G231 转换丢失 Q 引数**: 三菱 `G31 Y[#1-#32] F#119` 转换后变 `G231 Y(#1-#32) F#7019` 不带 Q, 但一线实际用 `G31 ... Q(105+(#1508-1)*1)` 保留 Q 引数做多通道轴群关联. 转换工具的 G231 无 Q 与一线 G31 带 Q 的差异需人工修正.
2. **`#1361` → `@1361` 丢失多通道维度**: 三菱 `#5063`(探头测量值)转换工具映射到 `@1361`(单通道系统变量), 但一线用 `#[1361+(#1508-1)*3]` 按轴群 `#1508` 做偏移. 单通道 `@` 映射无法表达多通道轴群维度.
3. **刀长补偿 `#11000` 系列**: 转换工具用单通道 `#11000+#20`, 一线用 `#[31300+(#1508-1)*300+#20]` 按轴群偏移. 多通道需转成 `#33500` 段.
4. **POPEN/DPRNT/PCLOSE 三菱通信输出**: 三菱 `POPEN` 打开通信输出(文件/打印/关闭), 转换工具报不支持. 预期映射: `POPEN→OPEN`, `DPRNT→PRINT`, `PCLOSE→CLOSE`.
5. **程序头防护**: 一线程序头常见 `IF(#1506=1)THEN GOTO999; END_IF;` 做探头状态防护, 转换前/后均无, 需人工补.

### 4.3 `#1508` 轴群索引变量

`#1508` 是当前轴群编号, 一线程序广泛用 `(#1508-1)*N` 做多通道轴群偏移基准, 转换工具未处理此维度, 是探头程序多通道转换错误的主因.

## 5. 插件诊断相关结论

- 当前插件 `SYNTEC_UNSUPPORTED_*` 系列诊断覆盖发那科/三菱**语法层面**不兼容(运算符/比较符/赋值/控制流), 但**不覆盖变量号映射差异**(如 `#5063` vs `@1361` vs `#[1361+(#1508-1)*3]`)——变量映射属转换工具职责, 静态诊断无法判定意图.
- G31/G231 跳脱指令差异属转换工具输出问题, 非源程序语法错误, 插件不诊断.
- 多通道轴群偏移(`#1508` 维度)是运行时配置, 静态分析不判定.
- 本文档作转换工具改进与诊断规则扩展的参考资料; 若后续要新增「变量号映射可疑」类提示, 需先确认控制器变量表一手规格(见 [MACRO 知识与验证规划](MACRO知识与验证规划.md) 待补强项 §系统变量 bit 级规格表).
