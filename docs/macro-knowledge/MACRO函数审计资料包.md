## 2. 已核实的关键边界

### `GETARG` 与 `GETTRAPARG`

- `GETARG` 用于读取调用引数与扩充引数，例如 `GETARG(X)`、`GETARG(Z1)`。
- 引数不存在时，`GETARG` 回传 VACANT `#0`，调用方应自行检查，而不是假设为 `0`。
- `GETTRAPARG` 专门读取 `G66/G66.1` Trap 单节内的引数；它与 `GETARG` 的值来源不同。

### `SYSDATA`

- 官方函数表要求诊断变量号为整数；字符串和小数会触发 `COR-023`。
- 非数值形式会导致语法错误；超出诊断变量范围会触发 `COR-016`。
- 函数表列出的版本为 `10.118.23U`、`10.118.28H`、`10.118.33`；读取当前状态前建议 `WAIT()` 挡预解。
- 目前仅确认 `10000` 是越界示例，尚未取得完整且跨系统稳定的诊断变量编号上限，因此不加入范围 error。

### `DRVDATA`

- 站号须为整数。第二引数可使用十进位整数或符合 `"xxxh"` 的十六进位字符串，其中 `x` 仅能是 `0~F` 且结尾 `h` 为小写，例如 `"D61h"`。
- 无对应驱动器时回传 VACANT；不支援的状态变量会触发 `COR-016`；格式错误会触发 `COR-023`。
- 驱动器、站号、状态变量与开机后资料就绪时间均为运行时依赖，不能从单一文本调用推断成功与否。

### 4.1.1 Phase 5.1 CF 文档现状复核结论（2026-09-20）

CF TechManual《Macro Function List》中当前**未提供独立的 `GETPR` / `SETPR` 正式函数专页**（属于内部扩展/高版本支持函数）。CF 文档现状判定如下：

1. **证据等级判定**：由于缺乏 A 级（CF 独立专页）直接证据，必须严格依据 **B 级证据（控制器实测记录）** 作为 Rust parity 的 emit 准则；C/D 级（仓库历史、博客、口述）不可单独作 parity 依据。
2. **核心采集重点**（user 上控制器时按 [Phase5-控制器证据采集清单](Phase5-控制器证据采集清单.md) §B 表逐项采集）：
   - **签名与返回值**：`GETPR(prNo)` 与多轴群扩展签名 `GETPR(prNo, axisGroup)` 的返回值类型（数值 vs `VACANT` / `#0`）。
   - **异常报警**：越界参数编号是否触发 `COR-016`，超范围写入值是否触发 `COR-023` / `COR-024`。
   - **写入生效机制**：`SETPR` 的权限等级要求，以及写入后是即时更新还是需要重启控制器生效。
3. **不升级为静态 error**：在 user 上控制器完成 §4.1.1 采集之前，不新增参数范围、权限或写入时机诊断；hover 文案明确版本/编号仍待复核。

**这是 CF 文档现状判定，不是控制器实测记录**。Phase 5.2 Rust 跨行状态 struct 设计可以先行，但 `GETPR/SETPR` 相关 emit 入口仍要等 §4.1.1 B 级证据回填后才接入主循环。

## 4.2 Phase 5.1 控制器实测复核结论（2026-09-22）

user 于 Syntec 81RA / 11MA（CNC & 机器人通用测试平台）实机采集，软件版本 `10.120.44C` / `10.120.52`（x86 / ARM），采集日期 `2026-09-21`，采集人张颖。原始 6 块记录见 [Phase5-控制器实测现场记录单](Phase5-控制器实测现场记录单.md) §B，本节为面向资料包的复核结论归纳。

| 验证 ID | 函数调用 | 实测结果 | 警报编号 | 证据 |
| --- | --- | --- | --- | --- |
| FUN-A-13A | `GETPR(3401)` | 返回 Pr3401 实际值（如 `1000.0`）；返回类型 `float (Double)`；空值参数返回 `0.0` 而非 VACANT | 无 | 调前 `#1=0.0`，调后 `#1=1000.0` |
| FUN-A-13B | `GETPR(99999)` | 越界编号触发系统警报中断；变量不更新 | `COR-016`（不合法的参数编号） | 调前 `#1=123.0`，警报后 `#1` 保持 |
| FUN-A-13C | `SETPR(3401, 2000)` | 写入成功；Pr3401 由 `1000` 变 `2000`；运动相关实时参数即时生效 | 权限不足发 `COR-024` | 写前 1000，写后 2000；权限 1（厂商/维护级） |
| FUN-A-13D | `SETPR(99999, 100)` | 越界编号触发警报，未实际写入 | `COR-016` | `是否实际写入=否` |
| FUN-A-13E | `SETPR(3401, -99999999)` | 超范围值触发警报，拒绝写入并保持原值 | `COR-023`（参数设定值超出范围） | `是否实际写入=否` |
| FUN-A-13F | `GETPR(3401)` / `GETPR(3401, 2)` | `axisGroup` 可选第二引数完全支持；轴群 1 返轴群 1 专属值，轴群 2 返轴群 2 专属值 | 无 | 双引数多态签名确认 |

**核心结论收口**：

1. **签名**：`GETPR(prNo[, axisGroup])` — 单引数读当前轴群，双引数读指定轴群，多态重载完整支持。
2. **返回类型**：`float (Double)`；参数未初始化或空值时返回 `0.0` 而非 VACANT `#0`。
3. **越界写入/读取警报**：参数编号越界统一发 `COR-016`。
4. **超范围写入警报**：值超出参数上下限发 `COR-023`。
5. **权限等级**：`SETPR` 需权限 1（厂商/维护级），权限不足发 `COR-024`。
6. **生效机制**：运动相关实时参数即时生效；轴配置与构型参数（如 `Pr3201`）虽可写入但必须重开机生效。

**Rust parity emit 入口解锁**：本节 B 级证据回填后，Phase 5.3 Rust 端可针对 `GETPR/SETPR` 实现下列静态诊断 emit 入口（在 Phase 5.2-5.3 工作流中按四件套登记落地）：

- `GETPR/SETPR` 调用点引数个数检查（1 或 2 个引数）；超出则 emit `SYNTEC_FUNCTION_INTEGER_ARGUMENT` 或新增专用 code。
- 静态常量 `prNo` 越界检查（基于已采集的 `COR-016` 边界，但具体上下限仍依机型/轴群配置，默认不限范围）。
- `SETPR` 静态常量 `val` 范围检查（基于 `COR-023`，但具体上下限仍依参数定义，默认不限范围）。
- hover/QuickFix 文案补充权限等级、即时/重启二分与三种警报编号。

**风险与不可外推边界**：参数编号有效性、超范围上下限、权限等级实际拦截行为仍依控制器配置和参数定义；不静态推断具体参数号、不静态推断具体超范围阈值、不静态推断轴群数（多轴群机型由控制器配置决定）。
