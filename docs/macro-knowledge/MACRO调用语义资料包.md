## 2. 已核实语法与时序边界

### 2.1 `G65`、`G66`、`G66.1`

- `G65 P_ L_` 是单一宏程序调用；传入字母引数会映射到目标宏的 `#1` 至 `#26`，扩充引数须通过 `GETARG` 读取。
- `G66 P_ L_` 是模式宏调用，后续每个移动单节结束后触发指定程序，直至 `G67` 取消。
- `G66.1 P_ L_` 与 `G66` 共用模式宏的变量生命周期，但在每个单节结束后触发，不限于移动单节。
- `G65`、`G66`、`G66.1` 必须是该行最后一个 G 码；LTP 正式示例以 `COR-013` 说明该限制。若后面仍有 G 码，扩展给出 `SYNTEC_CALL_MACRO_NOT_LAST_G_CODE` warning。该诊断只检查文本顺序，不模拟控制器执行顺序。
- `G66` 建立的变量空间不与发出 `G66/G66.1` 的当前程序层共享，只在 `P` 指定的模式宏内共享，至 `G67` 回收。

### 2.2 `M98`、`M198`、`M99`

- `M98 P_ H_ L_` 调用子程序，`H` 省略时从文件开始执行；`P` 省略仅在记忆运转或 MDI 情境指向程序自身。
- `M198 P_ H_ L_` 必须有 `P`；缺失时会触发 `COR-052`。它只可调用档案型式副程序。
- `M198` 会在解译至该指令时强制重新读档；若 `M198` 被 `Pr3601~3610` 登录为 M 码调用宏，开档功能无效。
- `M98/M198` 的子程序继承调用方 `#1` 至 `#400`。子程序内执行 `M02/M30` 视同结束子程序并返回主程序。
- `M99` 无引数时返回 `M98/M198` 下一行；`M99 P_` 返回主程序指定 N 序号；`M99 Q_` 返回主程序指定行号。

### 2.3 预解限制

`WAIT()` 不能被当作“等待子程序完成”的通用同步原语。官方明确列出 `M98`、`M99`、`M198` 不在它的等待保证范围内；涉及调用和运动时序的程序必须通过图形模拟或实机验证。

### 3.1 CF CNC 范围复核

- TechManual 的 C-Type 页面明确记录：执行 `G66` 后，后续移动单节结束时再次执行指定宏程序；示例覆盖 `L2`、两次移动和 `G67` 取消。
- 当前 TechManual 的 `G66.1` 页面明确记录：每个单节结束后执行指定宏程序，并以移动、非移动、`M00`、`WAIT()`、模式恢复和 `M99` 展示触发边界。
- 上述页面没有给出最低控制器软件版本、机型选配条件或 81RA 例外说明，因此不能仅凭 CF 页面判定 81RA 差异的原因，也不能把该差异推广到 CNC。
- 插件继续只实现文本可确定的导航、Hover 和 CALL-13 warning；`G66/G66.1` 的触发频率及变量生命周期仍需 CNC 模拟器或控制器记录确认。

### 3.2 Phase 5.1 CF 规范范围复核结论（2026-09-20）

根据 CF 《MACRO 开发应用手册》与 C-Type 页面复核，并结合 81RA / 10.120.44C 首轮运行时记录，得出下列结论：

| 验证 ID | 指令与场景 | CF 官方规范结论 | 81RA 实测与 CNC 对比结论 | Parity 处理策略 |
| --- | --- | --- | --- | --- |
| CALL-RUN-01 | `G65` 宏调用与 `#27` 隈离 | 父/子程序局部变量独立阡离；宏程序执行完毕返回后，父程序局部变量恢复原值。 | 81RA 与 CF 规范一致（通过）。 | 变量生命周期表维持父子阡离语义。 |
| CALL-RUN-02 | `M98` / `M198` 子程序修改 `#27` | 父/子程序共用局部变量 (`#27` ~ `#400`)；副程序内的修改对父程序直接可见。 | 81RA 与 CF 规范一致（通过）。 | 子程序保持作用域穿透。 |
| CALL-RUN-03 | `G66` 模态宏调用 | 每个移动单节执行后触发一次，直到 `G67` 取消。 | **存在差异**：CF 明确为「每个移动单节后触发」，81RA 实测只触发 1 次。 | **CNC 控制器以 CF 规范为准**；81RA 差异作为机型分支特性处理，不相互外推。 |
| CALL-RUN-04 | `G66.1` 模态宏调用 | 每个单节（含移动与非移动单节）执行后均触发一次，直到 `G67` 取消。 | **存在差异**：CF 明确为「每个单节后触发」，81RA 实测只触发 1 次。 | **CNC 控制器以 CF 规范为准**；81RA 差异保留实机验证记录。 |
| CALL-RUN-05 | 运动 + `WAIT()` + `M98`/`M198` | `WAIT()` 仅针对插补与运动队列同步，对子程序调用无完成保证。 | 81RA 与 CF 规范一致（通过）。 | 维持现有时序判定模型。 |
| CALL-RUN-06 | `M198` 外部子程序调用 | 每次调用均重新开启并读取目标加工文件；Pr3601~3610 注册后失效。 | 81RA 与 CF 规范一致（通过）。 | 状态机需标记外部文件重读时机。 |
| CALL-RUN-07 | `M99` / `M99 P_` / `M99 Q_` | 分别返回下一单节、返回指定 N 序号单节、返回指定行号。 | 81RA 与 CF 规范一致（通过）。 | 跳转与行号解析已具备 parity。 |

**CALL-RUN-03/04 机型差异处理**：81RA 机器人系统上 `G66`/`G66.1` 均只触发一次，与 CF MACRO开发应用手册记载不一致。CF 规范作为 CNC 通用基线；Rust 侧状态机设计时以 CF 标准语义为默认模型，同时预留对 81RA 等特殊控制器的机型参数化适配（不互推、不畦一）。

**这是 Phase 5.1 的 CF 规范复核判定，不是 CNC 控制器实测记录**。后续 user 上 CNC 控制器时仍需按 [Phase5-控制器证据采集清单](Phase5-控制器证据采集清单.md) §A 表实际跑一轮，把「CNC 待测」列勾选后填入「CNC 实测」结论；仅凭 CF 文档判定不替代 B 级证据要求。
