## 本机开发与 GitHub 同步

1. 开始开发前运行 `git status --short`，确认当前分支和未提交改动。
2. 每个小批次先运行与改动匹配的验证；文档批次至少运行 `git diff --check`，代码批次至少运行 `npm.cmd test` 和 `npm.cmd run lint`。
3. 推送前确认 `git diff --check`、测试、lint 和文档同步检查通过，再检查 `git diff --stat` 与 `git status --short`。
4. 普通开发提交推送到 `main`；版本发布时才创建并推送 `vX.Y.Z` tag，发布流程仍以本文档后面的清单为准。
5. 推送后用 `git status --short` 确认本地状态，并在发布场景用 `git ls-remote --tags origin vX.Y.Z` 核对远端 tag。

## 当前架构入口

> v4.0.0 起 12 个 JS 分析器模块已退役 (净减 ~4218 行), 诊断/导航/格式化/补全主流程由 Rust/Wasm analyzer 产出, host provider 走 `src/hostRustAnalyzer.js` 同步路径.

### 扩展入口

- `src/extension.js`
  - VS Code provider 注册 (completion / hover / definition / references / workspace symbol / formatting / diagnostics / code-actions)
  - diagnostics collection 接管 worker 异步诊断结果
  - `setHostAnalyzerPolicy('empty')`: host 未就绪时 `getHostRustAnalyzer()` 返回 `null`, 所有 host provider 直接返回空结果, 不试图加载 JS fallback
- `src/validatorWorker.js`
  - 唯一 backend: `rust-wasm`, 通过 `src/rustWasmWorkerAdapter.js` 包装 wasm asset 加载 + analysis ABI
  - Worker 启动时加载生产 wasm asset (`assets/rust-wasm/`), 失败抛错由 `createAnalysisBackend` 回退

### Host-only helpers (Provider 层)

- `src/hostRustAnalyzer.js` — Rust 同步分析入口, 用于 host provider 即时响应
- `src/rustWasmAsset.js` — 生产 wasm asset 全链校验 (manifest/字节/SHA-256/instantiate/exports)
- `src/rustWasmWorkerAdapter.js` — Worker 端 Rust analyzer 高阶组合
- `src/diagnosticsProvider.js` / `src/completionProvider.js` / `src/hoverProvider.js` / `src/definitionProvider.js` / `src/navigationProvider.js` / `src/formattingProvider.js` — VS Code API 绑定, 把 host Rust 结果转成 VS Code 对象
- `src/pathResolver.js` — `collectNavigationIndexEntries`/`isPotentialNavigationFile`/`getProgramEntryName`/`getMacroProgramName`/`isMacroFileContent`/`extractNavigationSymbolsMetaOnly` 等 host-only 导航 helper
- `src/diagnosticCodes.js` — 稳定诊断 code 集合 (数据真源, 作 host/worker 共享)
- `src/diagnosticActions.js` — Quick Fix 替换规则、说明型 action 文案
- `src/providerShared.js` — Provider 共享缓存与开关 (`functionIndex` / `isFeatureEnabled` / 后端设置读取)

### 数据真源 (Phase R2: src/data/*.json + thin JSON loader)

- `src/data/systemVariables.json` + `src/systemVariables.js` — 系统变数编号语义 (hover)
- `src/data/functions.json` + `src/functions.js` — 内置函数表 (62 项 hover/completion)
- `src/data/hoverDocs.json` + `src/codeDocs.js` — G/M 码 hover 文档 (gCodeDocs/g10LCodeDocs/mCodeDocs 三表)
- `src/data/keywords.json` + `src/keywords.js` — 关键字分组 + keywordDocs (72 项 hover/completion)
- `src/completionSnippets.js` — `buildFunctionSnippet` 纯函数 (无数据真源, 不迁)
- `snippets/syntec-macro.json` — VSCode snippet 注册表 (已是 JSON)

### Rust/Wasm 核心

- `crates/syntec-core/src/lib.rs` — 唯一分析后端: 诊断 + 导航 + 格式化 + completion 元数据生成
- `assets/rust-wasm/{manifest.json, syntec_core.wasm}` — 生产 wasm 资产, 通过 `scripts/buildRustWasmAsset.js` 构建并 bundle 进 VSIX

### 文档与生成

- `docs/诊断规则与修复动作.md` — 诊断 code、分类、严重度、Quick Fix / CodeAction、说明
- `scripts/generateDiagnosticDocs.js` — 由 `diagnosticCodes` 与 `diagnosticActions` 生成诊断文档 (`--check` 模式比较不写入磁盘)
- `scripts/checkReleaseConsistency.js` — 校验 package 与 lockfile 一致性; `--tag vX.Y.Z` 模式校验 README/CHANGELOG 与发布 tag
- `scripts/checkVsixContents.js` — 严格校验 VSIX 必须包含与禁止包含的文件 (R2 后含 `src/data/*.json`)
- `scripts/reportVsixArtifact.js` — 输出 VSIX 字节数与 SHA-256
- `.github/workflows/ci.yml` — main 分支与 PR 自动运行测试、文档同步检查、ESLint 与 VS Code 集成测试
- `.github/workflows/rust-wasm.yml` — Rust/Wasm 跨平台构建矩阵 (Ubuntu + Windows) + smoke + perf-data 上传
- `.github/workflows/release.yml` — `--strict` readiness 门禁 + VSIX 打包 + 安装级 smoke + Release body 含 SHA-256
- `docs/macro-knowledge/README.md` — MACRO 知识、证据、规划和专题资料包统一入口

## 注意事项

- 不要把旧版 `.vsix` 留在仓库根目录，避免误装。
- `tests/fixtures/test-demo.nc` 应保持无诊断，用作合法语法覆盖样例。
- 错误场景应放在测试内联样例中，不应长期留在 demo 文件里。
- Quick Fix 只做安全机械修复；需要用户判断语义的场景使用说明型 action。
- 动态跳转目标不做静态解析，避免误跳。
