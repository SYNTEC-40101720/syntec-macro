## 2. 改写步骤（依赖图反向，从叶子到入口）

执行顺序由下至上，每步独立可 lint + test 验证。

### Step 2.0 — 架构前置: host-sync Rust analyzer 注入层（2026-09-21 新增识别）

> **关键 gap 识别**: 原 §2.5 把 host 同步 provider (`formattingProvider`/`navigationProvider`/`definitionProvider`) 的"改写为通过 Rust analyzer 路径"描述为简单替换, 但当前 v3.1.0 架构中 Rust analyzer 只在 `validatorWorker.js` 的 worker_threads 异步路径注入, host 同步 provider 至今仍直调 `src/analysisCore.js` (即 `analyzeDocument`/`formatDocument`/`analyzeNavigationDocument`). R1.2 剔除 `analysisCore.js` 前必须先补这层 host-sync Rust 注入基础设施, 否则上述 5 个 host provider 同步调用会断。

**新增模块**: `src/hostRustAnalyzer.js`

```js
// Host 端同步 Rust analyzer 加载与缓存。
// activate() 阶段 await 一次 wasm 实例初始化, 后续同步调用直接复用.
// 启动延迟期间 fallback policy 由配置项控制:
//   - 'defer' (推荐 v3.1.x): 启动期间返回 JS analyzer 结果 (v3.1.x 兼容
//     JS 仍存在时); R1.2 后切换为 'empty' (返回空 edits/symbols 而非真值)
//   - 'block': 启动期间抛错 (WASM 仍初始化中) — 仅适合同步强契约场景
```

**接入 `extension.js::activate`**: 在 host providers 注册前 await host analyzer 加载完成 (Promise), 在加载完成前 register 的同步 provider 接受可选 fallback analyzer 参数 (当前 JS analyzer 兼容期).

**provider 改造模板**:
```js
// formattingProvider.js (改造前)
const { formatDocument } = require('./analysisCore');
function provideDocumentFormattingEdits(document) {
  const result = formatDocument(request);
  return result.edits.map(...);
}

// 改造后 (v3.1.x R1.2-prep 阶段)
const { getHostAnalyzerOrFallback } = require('./hostRustAnalyzer');
const { formatDocument } = require('./analysisCore'); // v3.1.x 保留兼容
function provideDocumentFormattingEdits(document) {
  const analyzer = getHostAnalyzerOrFallback();
  // Host 端 Rust analyzer 已就绪走 Rust, 未就绪走 JS 兼容
  const result = analyzer.formatDocument
    ? analyzer.formatDocument(request)
    : formatDocument(request);
  return result.edits.map(...);
}

// R1.2 Stage B 完成后: 删除 require('./analysisCore') + analyzer.formatDocument
// 始终走, 启动未就绪由 hostRustAnalyzer 控制 fallback policy.
```

**为什么不直接 §2.5 替换**: 当前 host provider 5 个文件涉及 8 处同步直调, 一次性替换需同时引入 async wrapper 让 VS Code 同步 API 等 wasm 加载完成 (Promise→ awaited). 这种 loadable-sync 模式需要 PR 单独 review; 否则启动期诊断/格式化/nav 调用可能丢失. 本节由 2026-09-21 评估时新增识别.

**前置 PR ✅ 已落地 (2026-09-21, commit 待 push 后填上)**: 引入 `src/hostRustAnalyzer.js` + `src/extension.js::activate` 触发 init + `src/formattingProvider.js` 同步路径走 host analyzer (启动期 JS fallback 兼容) + `src/navigationProvider.js` 同步路径 (`provideDocumentSymbol`/`getReferenceTargetName`/`getDocumentProgramName`) 走 host analyzer; 加 `tests/hostRustAnalyzer.test.js` 12 项契约测试守卫 API/policy 状态机/init 幂等. R1.1/2 R readiness 与 compare:rust parity 不变 (v3.1.x 行为兼容). 注: `definitionProvider.js` 现已确认只依赖 `fileResolver` 纯 path helper (R1.2 时该路径不需要同步 analyzer); `getWorkspaceMacroFiles` 异步 nav batch 路径当前仍走 JS `analyzeNavigationDocument`, R1.2 Stage B 时再迁移到 `rustWasmWorkerAdapter` host 入口 (避免本 PR 同步加 async 路由复杂度). R1.2 Stage B 实施时只需 `setHostAnalyzerPolicy('empty')` 让同步路径不再回退 JS, 工作量由 ~30 文件降为 ~20 文件且无架构盲区.

删除 `require('./navigationSymbols')`；改为 `require('./pathResolver')`。`applyNavigationFileMetadata` 中的 `isMacroFileContent`/`getProgramEntryName`/`getMacroProgramName` 改用 `pathResolver` 的新镜像实现。

### Step 2.5 — 改写 `src/formattingProvider.js`

`formattingProvider.js:5` 当前 `require('./analysisCore').formatDocument`，退役后改为：

### Step 2.7 — 改写 `src/diagnosticsProvider.js`

`diagnosticsProvider.js:18` 改为 require §2.2 新建的 `src/diagnosticActions.js`（host-only）。

### Step 2.8 — 改写 `src/definitionProvider.js`

inline `fileResolver.buildFileCandidates` 或改为 require §2.3 新建的 `src/pathResolver.js`。

### Step 2.9 — 改写 `src/validatorWorker.js`

删除 `backend === 'javascript'` 分支；统一走 `rustWasmWorkerAdapter`。如果 backend 还报 'javascript'，记录 warning 并退化为不诊断（不再回退 JS 实体）。

### Step 2.10 — 改写 `src/rustWasmWorkerAdapter.js`

删除 `line 83` 处的 lazy `require('./analysisCore')`（loading 后 JS fallback 不再可能）。fallback 行为改为：

- 资产加载失败 → 抛 `RustWasmAssetError`，由 host 层捕获显示 banner 提示重装/扩展损坏
- 运行时分析失败 → 抛 `Error`，worker 终止此次调用并不返回结果（不再有 JS 兜底）

### Step 2.11 — 改写 `src/analysisBackend.js`

删除 `JAVASCRIPT_BACKEND` 分支：
```js
// 退役前：createAnalysisBackend({ backend }) → rust-wasm 或 javascript
// 退役后：只支持 rust-wasm，其他值抛 TypeError 'unsupported backend; only rust-wasm is available'
```
保留 `RUST_WASM_BACKEND` 单例创建；删除对 `analyzeDocument`（来自剔除的 `analysisCore.js`）的 require。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
